# MMSIM-5 — Evening screen: skill tree, journal, save/load (v1 scope M4)

Motivation: `docs/incremental-game-v1-scope.md` M4: evening screen with the skill tree (3 branches), journal lines, save/load. Layout stays basic (a Claude Design pass comes once every screen exists).

- IN:
  - **Skill tree as data** (`content/core/skillNodes.json`): a node has a branch, per-level `costs` (several = repeatable, one = unlock), `requires` (cross-branch links) and `effects`: `unlock` (adds an unlock id), `modifier` (per-level add to `capacity`, `counterSpace`, `patience`, `supply:<ingredient>`, `weight:<customerType>`) and `addStation`. 13 nodes: Kitchen (honey yield x4, bigger cauldrons x3, second cauldron, oven, dark seed garden), Shop (counter space x3, patience x3, recipe 2, recipe 3, clerk, contract board), Temple/Hive (the Faithful x3, hive bond x3). The engine action `buy` (evening only) spends coins; the UI dry-runs each purchase through the engine to show "Buy (cost)" or the reason it cannot be bought, so rules live only in the engine. Unlocks feed the existing `state.unlocks`, so everything built in M1-M3 (oven, garden, clerk, contracts) is now reachable by playing; the `?unlocks=` dev URL still works.
  - **Second cauldron**: a station type with `auto: {candy, quality}`; at the start of each day it runs its batches by itself (using the day's honey, before the player), and is hidden from the craft screen / refused by the engine. **Recipes**: candies have an optional `unlock`; two new ones (Sunflower brittle, Honey toffee). Customers only ask for unlocked recipes they could afford at their minimum quality.
  - **Evening screen** (`Evening.svelte`): day report, journal line, tree, save panel. **Journal** lines are data (`journal.json`) with simple conditions (day range, revenue, customers lost, clerk sales, owned node); `journalKey()` rotates by day number with no randomness so the seeded game is untouched.
  - **Save/load** (`src/save/`): versioned envelope (`SAVE_VERSION` 1) around the plain engine state, zod-validated and checked against current content ids; autosave to localStorage after every action (guarded, the game runs without storage); copy/paste export string (`CST1:` + base64) and import; "New game" with confirmation. Dev URLs (`?seed=` / `?unlocks=`) never read or write the real save. Load errors are codes translated at render time.
  - Simulator bot now buys the cheapest available upgrade each evening, so `npm run sim` shows a real progression curve.
- OUT (M5): errands board, rank milestones / weekly targets, map strip, rival pressure (the rest of the Temple/Hive branch), so that branch has 2 nodes for now. Not done: cloud saves, multiple save slots, undo, upgrade refunds.
- Rules fixed here (challenge in M6): unlock/addStation effects apply at level 1; modifiers scale with level and take effect the next morning (supply) or immediately (counter, patience for new arrivals, batch size); prices (20 to 110 coins per level) are placeholders; the auto cauldron competes with the player for the day's honey.
- Verified: `npm test` 63 passing (skill tree rules, auto station, recipe/customer rules, journal, save round trip incl. continuing play identically, export/import, rejection of garbage/future/unknown content), `npm run check` 0 errors, `npm run check:content` and `npm run build` clean; `npm run sim -- --days 60` runs (about 63 coins/day average, bot-dependent). In the browser: played day 1 to the evening, bought Counter space (40 -> 15 coins), reloaded and the evening state, coins and level came back, export -> new game -> import restored the exact same state, garbage import showed a translated error that re-translated on language switch, dev URL left the real save untouched, desktop and phone-width layouts checked.
- Open decisions: costs/effects need the M6 balance pass; the tree is a plain card list (the real tree layout is for the design pass); journal lines are placeholders for the author's own voice; no UI to see which node a locked one needs besides its name; whether upgrades should be buyable in the morning too.
