# MMSIM-3 — Craft screen (v1 scope M2)

Motivation: `docs/incremental-game-v1-scope.md` M2: craft screen with tap-to-place ingredient steps and image slots. Also sets the app name: "Cult of Sweet Tooth" (EN) / "Culte de Bec Sucré" (FR).

- IN: morning screen = `Board` (forecast, contracts with a Deliver button, candy stock) + `Craft` (workshop). A batch is built by hand: pick candy + quality, tap an ingredient on the shelf to hold it, tap the station to put one unit in (the ingredient stays held until all its units are in), then run the steps in order: Stir, the quality's extra steps (Bake in the oven for Fine), Shape. Finishing the last step dispatches the engine `craft` action. Pure step logic lives in `src/craft/session.ts` (no UI imports, unit-tested); `startSession` asks the engine itself (dry-run `craft`) whether the batch is allowed, so the rules have one source of truth. Day header (day, phase, coins), phase buttons for the other phases (afternoon/evening show a "not built yet" panel until M3/M4), language toggle, light/dark via `prefers-color-scheme`, 44px touch targets, no horizontal overflow at 375px.
- Image slots: every ingredient, candy and station must have an art slot `ingredient-<id>` / `candy-<id>` / `station-<id>` in `artSlots.json` (the content check fails otherwise); placeholders are SVGs at the final sizes (ingredients/candies 96x96, station 240x180) in `public/art/`. Swapping art = replacing the file.
- Data-driven bits: qualities got `extraSteps` (id + nameKey); the string check now finds `*Key` fields at any depth. `{name}` placeholders in strings via `t(key, params)`; the document title follows the language.
- OUT: afternoon/evening screens, skill tree (qualities/contracts are reached with the dev URL `?seed=N&unlocks=oven,dark-garden,contractBoard`), drag and drop, animations, real art, save/load, automation of steps (the clerk and the automated cauldron come later; manual steps must not become a chore by the ~50th batch, see the risk in `docs/incremental-game.md`).
- Non-obvious: the engine clones its state with `structuredClone`, which throws on Svelte reactive proxies, so the UI holds the engine state in `$state.raw` (`src/ui/game.svelte.ts`). The first version used plain `$state` and the Start button silently failed; found by playing it in the browser.
- Verified: `npm test` 38 passing, `npm run check` 0 errors, `npm run check:content` and `npm run build` clean. Played in the browser (dev server, since stopped): FR UI, plain batch end to end (2 honey taps, Stir, Shape -> 4 drops in stock, 2 batches left, supply counter updating), Perfect batch asks for honey and dark seed, no console errors, 375px viewport has no horizontal overflow. Not checked on a real phone, and the Fine/oven step was covered by unit tests only.
- Open decisions: 2-3 taps per ingredient unit will get tedious (candidate for a long-press or "fill" shortcut, or earlier automation); the shelf shows ingredients the batch does not need (greyed out); candy/station selection resets after each batch.
