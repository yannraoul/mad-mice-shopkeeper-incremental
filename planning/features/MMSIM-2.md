# MMSIM-2 — Engine and headless simulator (v1 scope M1)

Motivation: `docs/incremental-game-v1-scope.md` M1: engine only, no UI — day state machine, one recipe, quality tiers, customers, orders, revenue, headless simulator, tests.

- IN: `src/engine/` — `step(content, state, action)` is a pure reducer (clones the state; returns `{ok, state, events}` or `{ok:false, error}`); seeded PRNG kept inside the state, so runs are reproducible. Actions: `craft`, `fulfill` (contract), `serve`, `refuse`, `endPhase`. Morning craft, afternoon serve, evening roll-over to the next morning with a report pushed to `history`. `src/sim/` — a baseline bot and `simulate()`; `npm run sim -- --days 30 --seed 1 --unlocks oven,dark-garden,contractBoard` prints the revenue table. 27 new tests (engine rules, determinism, immutability, simulator).
- OUT: skill tree / unlock purchases (M4 — unlocks are just ids in `state.unlocks`, set by the caller for now), weekly targets and stages (M5), delegation/clerk automation (M3), errands, rival pressure, saves, any UI, substituting a different candy for what a customer wants (only 1 recipe in v1 content).
- Content became richer, still data only: qualities got `priceMult`, optional `unlock` and `extraIngredients`; ingredients `dailySupply`; stations `batchesPerDay`; customer types `weight`; new `forecasts.json` and a singleton `settings.json` (packs may override its keys). Loader validates the new cross-references.
- Rules fixed here (decisions to challenge in M6): ingredient supply resets every morning (no carry-over; candy stock does carry). A batch yields the station's `capacity` candies and costs the recipe once. Patience = number of other customers' actions (serve/refuse) a waiting customer tolerates, not time. Anyone still waiting when the afternoon ends is lost. Customer types whose minimum quality is not craftable yet do not arrive. The forecast row is drawn at random each morning and biases arrival count and type mix; the real count also has +-`arrivalNoise`. Contract quality means "at least", reward = unit price x qty x `contractMult`, expired contracts just vanish (no penalty). A higher quality may serve a lower requirement.
- Verified: `npm test` 32 passing, `npm run check` 0 errors, `npm run check:content` and `npm run build` clean; `npm run sim` runs 30 days (about 39 revenue/day with nothing unlocked, about 43 with oven + garden + contracts; the bot is naive, so this only proves the pipeline, not balance).
- Open decisions: numbers in `content/core/*.json` are placeholders until M6; whether unused ingredients should carry over; whether the bot should be smarter (stock planning against the forecast) before M6 balancing.
